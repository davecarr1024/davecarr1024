# MoonRock 0.50 recovery

This directory records a recovered MoonRock 0.50 toolchain and public source release.

## Provenance

- Download URL: `https://exmortis.narod.ru/comp_src/mrock50.zip`
- Retrieved: 2026-07-25
- Archive SHA-256: `71cb170e4e52de9a70aa8fdd023dbfa1e78eb8cc2781c4ab02d2e56ad085beb2`
- Archive size: 551,055 bytes
- Attribution in archive: Rowan Crowe / Jelly-Bean Software Development

The URL was indexed by multiple historical compiler lists as `mrock50.zip`. The archive itself identifies MoonRock as version 0.50 Beta and includes the compiler, linker, documentation, examples, ArrowSoft assembler, configuration files, and a nested `MRSRC017.ZIP` public-domain source release.

## Recovered contents

`toolchain/` contains the runnable release components and a working build configuration:

- `MRC.EXE` — MoonRock source-to-assembly compiler
- `MRLINK.COM` — linker
- `ASM.EXE` — ArrowSoft assembler extracted from `ARROWASM.ZIP`
- `MR-REF.DOC` and `MRHELP.COM` — command reference/help
- `HELLO.MOO` plus other sample programs
- `MOONROCK.ALB` and `MOONROCK.PTR` — compiler library metadata
- `MRC.CFG` — copied from the included `MRC-ASM.CFG` for ArrowSoft

`source-release/` contains `MRSRC017.ZIP`, extracted. It includes:

- `MRC.BAS`, `MRP2.BAS`, `MRP2A.BAS`, `MRMISC.BAS`, `MR-CMD.BAS`, and `MR-NUM1F.BAS`;
- extensive `.ASM` runtime/library code under `LIB/`;
- QuickBASIC and Visual Basic/DOS build files;
- object libraries and helper programs;
- bug reports and a partial rewritten compiler under `MM/`.

The source release says it is free for personal use, has no warranty, and prohibits commercial use. Its licensing text should be preserved and reviewed before redistribution beyond this personal research repository.

## Verified build

Using DOSBox 0.74-3 on this Linux machine:

```text
MRC HELLO.MOO
```

successfully produced:

- `HELLO.ASM` — 2,496 bytes
- `HELLO.OBJ` — 540 bytes
- `HELLO.COM` — 276 bytes

The generated assembly begins with:

```asm
; Generated by MoonRock 0.50 from sourcecode file HELLO.MOO
; * Compiled for smallest size.
; * Lowest target processor: 8086
```

Running `HELLO.COM` under DOSBox and redirecting its output produced:

```text
Hello world\r\n
```

This is the first independently reproduced original MoonRock build in the revival workspace.

## Historical implications

The recovery changes the status from “compiler not found” to “compiler and source recovered.” The next questions are now empirical:

1. Which graphics facilities are already present in `MR-REF.DOC` and the `LIB/` assembly?
2. Can the original toolchain compile direct VGA/mode 13h routines through inline assembly or `VIDCGA.ASM`?
3. Can the public source release rebuild `MRC.EXE`, or only document the compiler’s internals?
4. How closely does the partial `MM/` rewrite resemble the envisioned next-generation MoonRock?

The original compiler can now be treated as the compatibility oracle for a future MoonRock language project. Preserve its generated assembly and behavior before attempting a clean-room rewrite.

## Graphics findings

The recovered samples answer part of the original graphics question:

- `STARS.MOO` calls `SETGRAPHMODE(6)`, obtains a graphics segment with `GETGRAPHSEG`, allocates a second 16 KB buffer, switches buffers with `SETGRAPHSEG`, and uses `PUTPIXEL` plus `FARMEMCOPYS` for animation.
- `WDEMO.MOO` implements a text-mode offscreen buffer: it saves the real screen segment, allocates an intermediate 4,000-byte buffer, renders into it, then copies it back with `FARMEMCOPYS`.
- `VIDCGA.ASM` in the source release contains the graphics dispatch for CGA modes 4 and 5 and pixel routines. The public source release appears to be from an earlier generation than the 0.50 binary, so the exact `SETGRAPHMODE(6)` implementation should be traced through the generated assembly/library archive rather than assumed from that file alone.
- `MR-REF.DOC` documents `GETGRAPHSEG`, `SETGRAPHSEG`, `PUTPIXEL`, `GETPIXEL`, and direct screen-buffer manipulation.

This is a strong foundation for the proposed wedding cake, but it also gives us a historically accurate constraint: the first original MoonRock graphics target is likely a CGA/EGA-era graphics path, not automatically VGA mode 13h. Mode 13h can still be added as an explicit x86 macro/runtime extension, with its provenance clearly marked as a revival feature unless the 0.50 library proves it already exists.
